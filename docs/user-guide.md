# 安装、使用与游玩

更新时间：2026-11-03（CST）。

## 我只是想开始聊天

先让管理员装好插件、配置好模型，并导入你准备玩的卡包。你在聊天里发送 `角色卡使用 卡包ID`，收到开场白后接着说话就行。卡包 ID 以面板里显示的为准，显示名称不一定等于 ID。

没有开场白时，先看机器人是否收到了命令，以及当前会话是否已经绑定卡包。平时聊天需要怎样唤醒机器人，仍然按原来的 AstrBot 设置。

想知道进度就发 `角色卡状态`。想暂停就发 `角色卡停止`，以后在同一会话重新启用同一张卡，会接着原来的存档。`角色卡重置` 会让当前成员从头开始；不想重来时不要用它。

## 管理员第一次配置

按 README 安装 Python 依赖和 npm 依赖后，重载插件。在插件配置里选一个已经能正常调用的“专用状态审计模型”。审计模型负责读完这一轮聊天，判断场景、数值和事件有什么变化；它可以和主聊天使用同一个 Provider，但会多一次模型请求。

如果卡包明确写了 `state.update_mode: mvu`，就由主聊天模型在回复末尾带上变量更新指令。插件先检查、保存，再把这些指令从发给玩家的正文中拿掉。此模式本轮会关闭流式发送，等整条回复完成后发送；不需要额外审计模型。

不要因为聊天能回复就认定存档也在变化。先进行一轮明确的互动，再用 `角色卡状态` 核对，必要时查看 AstrBot 日志中的“状态审计”提示。没有符合变化条件时，数值保持原样是正常的。

## 导入和换卡

登录 AstrBot 后，从插件管理打开“角色卡面板”，选择 ZIP 或 JSON，点击导入。不要直接打开裸插件网页地址，正常入口会负责携带登录身份。

导入成功后看清卡包 ID，再到目标聊天中执行使用命令。切到另一张卡会使用另一份存档；原卡进度还在。群聊中，卡包绑定属于整个会话，每个成员的状态各自保存。

普通 V2 JSON 通常只有基础人设和开场白。要有阶段、事件池和 EJS，卡包本身需要包含运行时文件，或在 JSON 的 `data.extensions.astrbot_runtime.files` 中内嵌完整文件；插件不会凭空补出这些内容。

## 怎样更自然地推进剧情

把你正在做的事说清楚，比反复喊事件名称更有用。例如“把窗边的椅子拉过来，问他愿不愿意坐一会儿”，比“触发谈心事件”更容易形成明确的场景与互动。

给角色留一点回应空间。一轮里塞进邀请、表白、约会和结局，模型容易漏掉中间步骤，程序也不会因为文字里提到了结局就自动记为完成。先做一件事，看对方回应，再继续。

事件可能要求特定阶段、场景、前置经历或等待几轮。没出现时不必反复刷同一句话；继续正常相处，或查看卡包作者自己的攻略。使用动态事件池的卡，不一定依靠关键词选事件，是否启用关键词由作者配置决定。

数值、阶段和事件结算由卡包规则共同决定，不保证每次聊天都加分。不要把状态面板当成考试评分，也别把数值增长当作角色已经答应某件事。

## 更新同一张卡

同 ID 卡包会拒绝直接覆盖。请先停服备份插件数据目录，再在面板解除这个卡包的全部会话绑定，确认列表里没有剩余绑定，然后删除旧卡、导入新卡，最后重新绑定。

解绑不会删除玩家状态，但保留数据库不等于新版一定兼容旧存档。新卡若改了 ID、阶段名或变量结构，先按作者的迁移说明处理；没有说明时用独立测试会话检查，别直接重置正式存档来试错。

## 常见卡点

| 看到什么 | 先做什么 |
| --- | --- |
| 一直聊天但状态没变 | 看卡包是 audit 还是 mvu；audit 模式确认 Provider ID 已配置，再看日志有没有审计失败 |
| 提示找不到 Node 或 EJS | 在实际运行 AstrBot 的环境执行 `node --version`，到插件目录执行 `npm ci --omit=dev --ignore-scripts` |
| 卡包已存在 | 不要反复导入，按上面的更新流程处理 |
| 提示卡包正在使用 | 在“会话绑定”中解除全部对应绑定，不只解除你自己的聊天 |
| 卡包没出现在列表 | 查看面板 diagnostics 或 `角色卡列表` 的具体解析错误，检查 manifest 引用的文件 |
| 正文出现 UpdateVariable 或 XML 标签 | 核对是否启用 mvu、模型是否完整输出规定格式，以及是否有其他插件改写回复；Live/TTS 和第三方 agent 尚未验收 |
| 状态图字体不对 | 把 `status_font_path` 指向服务器能读取的中文字体，或使用内置字体 |

成人事件默认关闭，只能在私聊主动开启，群聊不能开启。开关只代表允许此类事件进入候选，卡包自己的条件仍要满足。

卡包会执行 EJS 时，相当于允许运行本地代码。来源不明、作者不可信的模板，不要直接导入到自己的机器人。
